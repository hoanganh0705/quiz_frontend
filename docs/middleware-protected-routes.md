# Middleware protected routes — inventory

> Generated by **ET-1.6-A1** and annotated by **ET-1.6-A2** — Epic 1.6, Batch A.
> Source code: `quiz_frontend/src/proxy.ts` (Next.js 16 renamed `middleware.ts` to `proxy.ts`; the file-level intent and the inventory contract are unchanged).

This file lists every URL prefix the middleware redirects to `/login?redirect=<original>` when the access-token cookie is absent. **If a prefix is added to or removed from `proxy.ts`, both the inventory and the annotation must be regenerated in the same commit.**

---

## Summary

- **Protected prefixes:** 12 (see `PROTECTED_PREFIXES` constant, lines 5–16 of `proxy.ts`).
- **Admin prefixes:** 1 (`/admin`, `ADMIN_PREFIXES` constant).
- **Match mechanism:** `pathname.startsWith(prefix)` against the union of `PROTECTED_PREFIXES ∪ ADMIN_PREFIXES` (see `isProtected()`).
- **Redirect target:** `/login?redirect=<original-pathname>`.
- **Authentication signal:** presence of the cookie returned by `getAuthTokenFromRequest(request)`. **The cookie is *not* cryptographically verified** — see `proxy.ts` header for details.

## Source-of-truth split (route-group consistency refactor)

The project now follows the route-group convention that mirrors `app/(public)/`:
**every protected route lives under `app/(protected)/**` in source.**

- `proxy.ts` (`PROTECTED_PREFIXES` + `ADMIN_PREFIXES`) is the source of truth for **which URL prefixes** are gated.
- `app/(protected)/**` is the source of truth for **where the protected route components live** in source.

The `/admin`, `/social`, `/instances`, `/notifications`, `/tournaments` folders were migrated into `app/(protected)/**` so that the folder structure itself signals "this requires auth". The folder layout under `app/(protected)/` (alphabetical) is:

```
app/(protected)/
├── _components/         ← shared client wrappers (e.g. ProtectedShell)
├── admin/               ← admin console
├── bookmarks/           ← saved quizzes
├── create-quiz/         ← quiz authoring
├── discussions/         ← comment threads
├── friends/             ← social graph
├── instances/           ← live quiz sessions
├── my-profile/          ← current user's profile
├── my-quizzes/          ← user's quiz dashboard + version history
├── notifications/       ← notification center + preferences
├── onboarding/          ← first-run UX
├── quiz-history/        ← attempt history
├── quizzes/[idOrSlug]/attempt/  ← quiz-attempt runtime
├── settings/            ← account preferences
├── social/              ← social-graph lists
├── tournament/          ← singular tournament landing
└── tournaments/         ← plural tournament listings + detail
```

`(protected)` is a Next.js route group: the parentheses make it URL-invisible, so `app/(protected)/admin/page.tsx` still resolves to `/admin`. The `(protected)/layout.tsx` root layout wraps every page in `<ProtectedShell>`, a client-side belt-and-braces auth check that catches the rare case where the cookie is cleared between the server-side redirect and client hydration.

## Findings (ET-1.6-A2)

### Finding F1 — `onboarding` is gated before any auth signal is required by the backend (informational)

The `onboarding` flow is gated by the middleware even though none of the data shown on screen needs an authenticated session. The recommended action is **leave as-is**: gating the entire onboarding wizard prevents the user from accidentally racing the wizard twice in two tabs and means the redirect-after-login target is meaningful. No code change required.

### Finding F2 — `/admin` middleware is "any authenticated user", not "admin role" (real gap, deferred)

**Detail.** `middleware.ts` adds `/admin` to the same `PROTECTED_PREFIXES ∪ ADMIN_PREFIXES` union guarded by `isProtected()`. That guard only requires a token's *presence* (line 47: `const isAuthenticated = !!token`). It does **not** check that the token belongs to a user with the admin role.

**Backend-side role enforcement is real** (`quiz_backend/src/modules/*/transport/controller/*-admin.controller.ts` controllers exist and all carry `@Permissions(...)` decorators). So a non-admin who reaches the `/admin` page will get a 401/403 from the first admin API call — not from the middleware.

**Recommended action (deferred).** Two options; both are out of scope for ET-1.6-A2 because this ticket is read-only:

1. **Keep current behaviour.** Treat the middleware as "presence-only" and rely on backend `JwtGuard` + `@Permissions` for the real enforcement. This matches the doc policy in the middleware header.
2. **Strengthen middleware later.** A future ticket should parse the JWT's `roles` claim inside the middleware (subject to the Next.js 16 server-side validation capability — see the `TODO: server-side validation` line in `middleware.ts`). This ticket recommends tracking option 2 as a Phase-2 ticket; **do not fold it into this batch**.

### Finding F3 — `discussions` wording split between frontend and backend (informational)

The frontend URL is `/discussions` but the backend route prefix is `/comments`. The mapping is by intent (forum/discussion threads ↔ comment entities), not by URL name. Recommended action: **leave as-is**. A rename would touch every link in the app and the OpenAPI stub. Capture the terminology split in onboarding docs instead.

### Finding F4 — `/api` is in `PUBLIC_ROUTES` but there is no `app/api/*` segment (informational)

`middleware.ts` line 24 lists `'/api'` among the public prefixes, and `isPublic()` exempts any pathname starting with `/api` from the rest of the middleware. **There is no `quiz_frontend/src/app/api/` directory in this repo** (all backend-bound calls live under `src/lib/api/` SDK and are invoked from server/client components). The exclusion is therefore a no-op today. Recommended action: **leave as-is** (harmless, and future-proof if route handlers are added).

## Excluded paths (ET-1.6-A4)

The middleware has **two** layers of exclusion:

1. **Next.js `matcher`** (lines 74–85 of `middleware.ts`) — controls *whether the middleware is invoked at all* for a given request path. Anything not matched here never enters the middleware function.
2. **`isPublic()` early return** (lines 34–36, 41–44) — inside the middleware, paths that match `PUBLIC_ROUTES` short-circuit to `NextResponse.next()`.

| Pattern | Layer | Excluded because | Code ref | Intentional? |
|---|---|---|---|---|
| `_next/static` | matcher | Next.js bundles (`/static/chunks/...`). The middleware cannot rewrite them. | `middleware.ts:83` | ✅ Intentional. Standard Next.js exclusion. |
| `_next/image` | matcher | Next.js image-optimizer responses (rewritten via `next/image`). | `middleware.ts:83` | ✅ Intentional. Standard. |
| `favicon` | matcher | Favicon requests (matches `favicon.ico` plus any future `favicon-32.png`). | `middleware.ts:83` | ✅ Intentional. |
| `robots` | matcher | `robots.txt` is served by `app/robots.ts`; rewriting it would break crawlers. | `middleware.ts:83` | ✅ Intentional. |
| `sitemap` | matcher | `sitemap.xml` is served by `app/sitemap.ts`. | `middleware.ts:83` | ✅ Intentional. |
| `.*\\..*$` | matcher | Any URL with a file extension (`.png`, `.svg`, `.webp`, `.css`, `.js`, etc.) is treated as a static asset. | `middleware.ts:83` | ✅ Intentional. Prevents redirect loops on inline asset requests. |
| `/api` | `isPublic()` | Skips rewrites for `/api/*` paths inside the middleware function. | `middleware.ts:24, 34–44` | ⚠️ **Intentional but a no-op today** — there is no `app/api/*` route segment; see Finding F4. |
| `/_next` | `isPublic()` | Defensive belt-and-braces in case the matcher regex is loosened in future. | `middleware.ts:24, 34–44` | ✅ Intentional. Defensive duplicate of the matcher exclusion. |
| `/favicon` | `isPublic()` | Defensive duplicate of the matcher exclusion. | `middleware.ts:24, 34–44` | ✅ Intentional. Defensive duplicate. |
| `/manifest` | `isPublic()` | Web app manifest. | `middleware.ts:24, 34–44` | ⚠️ **Intentional gap**: the matcher does **not** exclude `/manifest` today. If a manifest file is ever served, the `isPublic()` early-return covers it. If `isPublic()` is removed, `/manifest` would enter the middleware — currently no public-page behavior is gated, so the impact would be no-op. Recommendation: leave as-is (current behaviour is correct). |
| `/sw` | `isPublic()` | Service-worker files. | `middleware.ts:24, 34–44` | ⚠️ **Intentional gap**: same comment as `/manifest`. No service worker exists today. |

### Coverage summary (ET-1.6-A4)

- All standard Next.js exclusions (`_next/static`, `_next/image`, `favicon`, `robots`, `sitemap`, files-with-extensions) are present in the `matcher`.
- The two-layer exclusion (matcher + `isPublic()`) overlaps on `_next/static`, `_next/image`, `favicon`. The duplication is intentional and harmless.
- The `isPublic()`-only entries (`/api`, `/manifest`, `/sw`, `/_next`) are present as a defence-in-depth measure. `/api` is a no-op today; `/manifest` and `/sw` are no-ops today.
